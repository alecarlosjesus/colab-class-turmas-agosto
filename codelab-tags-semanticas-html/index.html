🧱 Ideia central: uma página semântica funciona como uma construção bem sinalizada. header, nav, main, article, section, aside e footer informam claramente a função de cada região.

Neste codelab você aprenderá a escolher tags HTML pelo significado do conteúdo, e não pela aparência que o navegador aplica. Ao final, você construirá uma página completa com cabeçalho, navegação, conteúdo principal, artigos, seções, conteúdo complementar, figuras, listas, tabela, informações de contato e rodapé.

Objetivos de aprendizagem

Ao concluir, você conseguirá:

  • explicar o que é HTML semântico;
  • diferenciar estrutura, significado e apresentação visual;
  • escolher entre article, section, div e aside;
  • organizar títulos com h1 a h6;
  • marcar textos, listas, citações, datas, códigos, mídias e tabelas corretamente;
  • reconhecer elementos semânticos menos frequentes;
  • melhorar acessibilidade, SEO e manutenção semântica;
  • validar uma página antes de entregá-la.

Pré-requisitos

  • editor de código, como Visual Studio Code;
  • navegador atualizado;
  • conhecimentos básicos de arquivos e pastas;
  • noções iniciais de HTML.

Semântica é o significado atribuído ao conteúdo. Uma tag semântica informa o que aquele conteúdo representa.

Compare:

<div class="topo">Portal do Campus</div>
<div class="menu">...</div>
<div class="conteudo">...</div>

Com:

<header>Portal do Campus</header>
<nav aria-label="Navegação principal">...</nav>
<main>...</main>

As duas versões podem receber o mesmo CSS. Porém, a segunda comunica que existem um cabeçalho, uma área de navegação e um conteúdo principal.

Semântica não é aparência

Não escolha uma tag porque ela aparece em negrito, grande ou itálico. Aparência pertence ao CSS.

<!-- Incorreto: escolher h2 apenas porque o texto fica grande. -->
<h2>R$ 49,90</h2>

<!-- Melhor: o preço é um parágrafo com uma classe de estilo. -->
<p class="preco">R$ 49,90</p>

Por que usar HTML semântico

  1. Acessibilidade: leitores de tela podem anunciar regiões, títulos, listas, tabelas e controles.
  2. Manutenção: outro desenvolvedor entende a estrutura com menos esforço.
  3. SEO: mecanismos de busca recebem pistas melhores sobre a organização do conteúdo.
  4. Consistência: elementos nativos já possuem comportamentos e relações conhecidos.
  5. CSS e JavaScript: seletores podem refletir a estrutura real do documento.

Semântica ajuda o SEO, mas não garante boa posição em buscas. Qualidade, relevância, desempenho e muitos outros fatores também importam.

Estrutura mínima correta

<!doctype html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Portal do Campus</title>
  </head>
  <body>
    <header></header>
    <main></main>
    <footer></footer>
  </body>
</html>

O lang="pt-BR" ajuda mecanismos de busca, corretores e leitores de tela a interpretar a pronúncia e o idioma.

Os elementos h1, h2, h3, h4, h5 e h6 representam títulos em níveis hierárquicos.

Elemento

Uso típico

h1

Título principal da página.

h2

Grandes seções do conteúdo.

h3

Subseções de uma seção h2.

h4 a h6

Divisões progressivamente mais profundas.

Uma estrutura coerente:

<main>
  <h1>Guia do estudante</h1>

  <section>
    <h2>Biblioteca</h2>
    <h3>Horários</h3>
    <h3>Empréstimos</h3>
  </section>

  <section>
    <h2>Laboratórios</h2>
    <h3>Regras de uso</h3>
  </section>
</main>

Regras práticas

  • Use um h1 claro para identificar o assunto principal da página.
  • Não escolha o nível pelo tamanho visual; altere tamanhos com CSS.
  • Evite saltar de h2 diretamente para h4 sem uma razão estrutural.
  • Um título deve descrever o conteúdo que vem depois dele.
  • Não use títulos vazios apenas para criar espaçamento.

O elemento hgroup

hgroup agrupa um título com conteúdo secundário relacionado, como subtítulo ou linha de apoio.

<hgroup>
  <h1>Semana de Tecnologia</h1>
  <p>Ideias que conectam pessoas e transformam o campus</p>
</hgroup>

Ele não é obrigatório. Use-o quando essa relação realmente existir.

Exercício rápido

Corrija a hierarquia abaixo:

<h3>Portal acadêmico</h3>
<h1>Cursos</h1>
<h4>Desenvolvimento Web</h4>
<h2>Banco de Dados</h2>

Uma solução possível estará na etapa de respostas.

header

Representa conteúdo introdutório ou um conjunto de recursos de navegação. Pode conter logotipo, título, busca ou navegação.

<header>
  <p class="logo">Conecta Campus</p>
  <h1>Portal do estudante</h1>
</header>

header pode aparecer no documento e dentro de article ou section. Ele não significa obrigatoriamente "a faixa no topo da tela".

nav

Representa um bloco importante de links de navegação. Não é necessário envolver todo pequeno grupo de links em nav.

<nav aria-label="Navegação principal">
  <ul>
    <li><a href="index.html">Início</a></li>
    <li><a href="cursos.html">Cursos</a></li>
    <li><a href="contato.html">Contato</a></li>
  </ul>
</nav>

Se houver mais de uma navegação, forneça rótulos diferentes:

<nav aria-label="Navegação principal">...</nav>
<nav aria-label="Navegação do rodapé">...</nav>

main

Representa o conteúdo dominante e exclusivo da página.

<main id="conteudo-principal">
  <h1>Notícias do campus</h1>
  <!-- conteúdo principal -->
</main>

Boas práticas:

  • mantenha apenas um main visível por documento;
  • não coloque o main dentro de header, footer, nav, article ou aside;
  • cabeçalho, navegação repetida e rodapé geralmente ficam fora dele.

footer

Representa o rodapé do documento ou da seção à qual pertence. Pode conter autoria, direitos autorais, contatos e links relacionados.

<footer>
  <p><small>&copy; 2026 Conecta Campus</small></p>
</footer>

Assim como header, um footer pode existir dentro de um article.

Monte o primeiro esqueleto

<body>
  <a href="#conteudo-principal">Pular para o conteúdo principal</a>

  <header>
    <p>Conecta Campus</p>
    <nav aria-label="Navegação principal">
      <ul>
        <li><a href="index.html">Início</a></li>
        <li><a href="noticias.html">Notícias</a></li>
      </ul>
    </nav>
  </header>

  <main id="conteudo-principal">
    <h1>Portal do estudante</h1>
  </main>

  <footer>
    <p><small>&copy; 2026 Conecta Campus</small></p>
  </footer>
</body>

article: conteúdo independente

Use article para uma unidade que poderia ser distribuída ou reutilizada separadamente: notícia, postagem, comentário, card de produto ou verbete.

<article>
  <header>
    <h2>Inscrições para a maratona de programação</h2>
    <p>Publicado em <time datetime="2026-09-15">15 de setembro de 2026</time></p>
  </header>

  <p>As equipes podem realizar a inscrição até sexta-feira.</p>

  <footer>
    <p>Texto da equipe de Tecnologia</p>
  </footer>
</article>

Pergunta de decisão: "Este conteúdo ainda faz sentido se for copiado para outro lugar?" Se sim, article pode ser adequado.

section: agrupamento temático

Use section para agrupar conteúdo sobre um mesmo tema quando não houver elemento mais específico. Normalmente ela deve possuir um título.

<section>
  <h2>Serviços da biblioteca</h2>
  <p>Consulte empréstimos, reservas e horários.</p>
</section>

Não use section apenas para aplicar CSS. Para um contêiner sem significado próprio, use div.

article ou section?

Pergunta

Melhor escolha provável

É uma unidade independente e reutilizável?

article

É uma parte temática de algo maior?

section

Só preciso de uma caixa para layout?

div

É conteúdo lateral ou complementar?

aside

Um article pode conter várias section, e uma section pode agrupar vários article.

aside: conteúdo complementar

Representa conteúdo relacionado indiretamente ao conteúdo ao redor, como glossário lateral, biografia curta, links relacionados ou curiosidade.

<aside aria-labelledby="dica-titulo">
  <h2 id="dica-titulo">Dica de estudo</h2>
  <p>Reserve vinte minutos por dia para praticar HTML.</p>
</aside>

aside não significa apenas "coluna da direita". Sua posição visual é responsabilidade do CSS.

address: contato relacionado

Use para informações de contato do documento ou do article mais próximo.

<address>
  Coordenação de Tecnologia<br>
  <a href="mailto:tecnologia@example.com">tecnologia@example.com</a>
</address>

Não use address para qualquer endereço postal citado em um texto, nem para envolver data de publicação.

search: área de pesquisa ou filtro

search identifica um conjunto de controles usados para pesquisar ou filtrar conteúdo. Ele representa a interface de busca, não os resultados.

<search>
  <form action="/buscar" method="get">
    <label for="busca">Buscar no portal</label>
    <input id="busca" name="q" type="search">
    <button type="submit">Buscar</button>
  </form>
</search>

Listas não ordenadas

Use ul quando a ordem dos itens não altera o sentido.

<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>

Listas ordenadas

Use ol quando a sequência, posição ou contagem for importante.

<ol>
  <li>Crie a pasta do projeto.</li>
  <li>Crie o arquivo index.html.</li>
  <li>Abra o arquivo no navegador.</li>
</ol>

li só deve representar um item dentro de ul, ol ou menu.

Lista de descrições

Use dl para pares de termos e descrições. dt representa o termo; dd, a descrição.

<dl>
  <dt>HTML</dt>
  <dd>Linguagem de marcação usada para estruturar o conteúdo.</dd>

  <dt>CSS</dt>
  <dd>Linguagem usada para definir a apresentação.</dd>
</dl>

menu

menu representa uma lista não ordenada de comandos, como uma barra de ferramentas. Na prática, os navegadores o expõem de modo semelhante a ul.

<menu>
  <li><button type="button">Copiar</button></li>
  <li><button type="button">Compartilhar</button></li>
</menu>

figure e figcaption

figure representa conteúdo autocontido referenciado pelo fluxo principal, como imagem, diagrama, trecho de código ou tabela. figcaption fornece a legenda.

<figure>
  <img
    src="imagens/ambiente-de-estudo.jpg"
    alt="Monitor exibindo código de uma página Web"
    width="1000">
  <figcaption>Ambiente usado durante a prática de HTML.</figcaption>
</figure>

O alt descreve a função ou a informação relevante da imagem. Uma legenda visível não substitui automaticamente o alt.

picture, source e img

picture permite oferecer fontes alternativas para diferentes condições. img continua sendo obrigatório como opção final.

<picture>
  <source media="(min-width: 900px)" srcset="banner-grande.webp">
  <source media="(min-width: 500px)" srcset="banner-medio.webp">
  <img src="banner-pequeno.webp" alt="Estudantes reunidos no laboratório">
</picture>

<video controls width="640" poster="capa-video.jpg">

  <source src="apresentacao.mp4" type="video/mp4">

Função

audio

Incorpora conteúdo sonoro.

video

Use tabelas para dados tabulares, nunca para montar o layout visual da página.

Elemento

Função

table

Contêiner da tabela.

caption

Título ou descrição da tabela.

thead

Grupo de linhas de cabeçalho.

tbody

Grupo principal de dados.

tfoot

Grupo de resumo ou rodapé.

tr

Linha.

Célula de cabeçalho.

Célula de dado.

colgroup, col

Definem grupos e propriedades de colunas.

<table>
  <caption>Horários dos laboratórios</caption>
  <thead>
    <tr>
      <th scope="col">Laboratório</th>
      <th scope="col">Abertura</th>
      <th scope="col">Fechamento</th>
    </tr>
  </thead>
  <tbody>
    <tr>

details e summary

Criam uma região expansível nativa. summary é o rótulo acionável.

<details>
  <summary>Quais documentos devo levar?</summary>
  <p>Documento com foto e comprovante de matrícula.</p>
</details>

O atributo open deixa a região inicialmente aberta.

<details open>
  <summary>Aviso importante</summary>
  <p>O laboratório fechará às 18h.</p>
</details>

dialog

Representa uma caixa de diálogo. Uma caixa modal deve ser aberta com JavaScript usando showModal(); o atributo open sozinho cria uma caixa não modal.

<dialog id="confirmacao">
  <h2>Confirmar inscrição</h2>
  <p>Deseja continuar?</p>
  <form method="dialog">
    <button value="cancelar">Cancelar</button>
    <button value="confirmar">Confirmar</button>
  </form>
</dialog>

meter, progress e output

<p>
  Uso do armazenamento:
  <meter min="0" max="100" value="72">72%</meter>
</p>

<label for="envio">Envio do arquivo:</label>
<progress id="envio" max="100" value="35">35%</progress>

<p>Resultado: <output name="resultado">42</output></p>
  • meter mede um valor conhecido dentro de uma faixa.
  • progress representa o avanço de uma tarefa.
  • output representa o resultado de um cálculo ou ação.

E as tags antigas?

Elementos como font, center, marquee, frameset, frame, big, tt, strike, acronym e applet são obsoletos ou não conformes. Eles podem aparecer em sistemas antigos, mas não devem ser usados em projetos novos. Substitua apresentação por CSS e escolha elementos atuais pelo significado.

"Todas as tags" não significa usar todas na mesma página. Significa conhecer o catálogo e selecionar apenas as que descrevem corretamente o conteúdo e o comportamento necessários.

div e span

div e span são contêineres sem significado específico.

  • div agrupa conteúdo de fluxo, normalmente em bloco.
  • span agrupa um trecho curto dentro de uma linha.

Eles não são proibidos. São corretos quando não existe elemento semântico mais adequado.

<div class="grade-de-cards">
  <!-- agrupamento necessário apenas para o layout -->
</div>

<p>Vagas disponíveis: <span class="quantidade">12</span></p>

HTML nativo antes de ARIA

Prefira:

<button type="button">Abrir menu</button>

Em vez de recriar um botão com:

<div role="button" tabindex="0">Abrir menu</div>

O botão nativo já possui foco, ativação por teclado e semântica esperada. ARIA complementa o HTML; não adiciona automaticamente comportamento.

Erros frequentes

Erro

Correção

Usar section como qualquer caixa de layout

Use div quando não existir agrupamento temático.

Criar todas as regiões com div

Escolha header, nav, main, article, aside e footer quando representarem o conteúdo.

Usar aside apenas porque algo aparece à direita

Decida pela relação complementar, não pela posição.

Usar strong para deixar tudo em negrito

Use CSS quando a intenção for apenas visual.

Usar br várias vezes para espaçamento

Use margem ou espaçamento no CSS.

Usar tabela para montar colunas

Use Grid ou Flexbox no CSS.

Colocar li fora de uma lista

Envolva-o em ul, ol ou menu.

Adicionar role redundante a todo elemento

Use o elemento nativo e adicione ARIA somente quando necessário.

O que verificar no navegador

  1. A página abre sem erros visíveis.
  2. O título da aba é "Conecta Campus".

  4. Localize header, nav, main, section, article, aside e footer.
  5. Confirme que o main não está dentro de outra região inadequada.

Navegue apenas com teclado

  1. Recarregue a página.
  2. Pressione Tab repetidamente.
  3. Confirme que links, botões e summary recebem foco visível.
  4. Pressione Enter para ativar links.
  5. Pressione Espaço ou Enter para ativar botões e o resumo expansível.

Desafio 1 — escolha a tag

Escolha o elemento mais adequado para cada conteúdo:

  1. Uma postagem que pode ser compartilhada separadamente.
  2. A principal navegação do site.
  3. Uma caixa usada apenas para organizar quatro cards com CSS Grid.
  4. Um aviso complementar relacionado a uma notícia.
  5. O conteúdo exclusivo daquela página.
  6. Uma data de publicação legível por máquinas.
  7. Uma sigla com a forma completa disponível.

Mapa mental de decisão

  • É o conteúdo principal? Use main.
  • É navegação importante? Use nav.
  • É independente? Considere article.
  • É um agrupamento temático? Considere section.
  • É complementar? Considere aside.
  • É somente uma caixa para layout? Use div.
  • É somente um trecho para estilo? Use span.
