📝 Ideia central: um formulário é uma conversa estruturada. O label apresenta a pergunta, o controle recebe a resposta, o name identifica o dado e o servidor decide como processá-lo.

Formulários permitem que pessoas enviem dados: pesquisa, login, cadastro, contato, pagamento, filtros, upload e muitas outras interações. Um formulário bem construído precisa ser compreensível, operável por teclado, validado e processado com segurança no servidor.

Objetivos

Ao concluir, você conseguirá:

  • explicar o fluxo de envio de um formulário;
  • configurar form, action, method e enctype;
  • relacionar label e campo corretamente;
  • usar todos os tipos principais de input;
  • escolher entre input, textarea, select e datalist;
  • agrupar controles com fieldset e legend;
  • configurar validação nativa;
  • diferenciar disabled de readonly;
  • decidir entre GET e POST;
  • reconhecer limites de segurança e validação do front-end;
  • testar os pares nome–valor enviados.

O elemento form agrupa controles que participam de uma operação de envio.

<form action="/contatos" method="post">
  <label for="nome">Nome</label>
  <input id="nome" name="nome" type="text">

  <button type="submit">Enviar</button>
</form>

Quando a pessoa envia:

  1. o navegador verifica as regras nativas de validação;
  2. identifica os controles participantes;
  3. monta pares usando name e o valor de cada controle;
  4. codifica os dados;
  5. envia uma requisição ao endereço em action;
  6. o servidor valida, processa e devolve uma resposta.

No exemplo, uma entrada possível seria:

nome=Ana

id e name não são a mesma coisa

<label for="email-contato">E-mail</label>
<input
  id="email-contato"
  name="email"
  type="email">
  • id identifica o elemento no documento e o conecta ao label.
  • name define a chave usada no envio.

Sem name, o valor do campo normalmente não é incluído nos dados enviados.

O formulário não cria um backend

action="/contatos" pressupõe que exista uma aplicação no servidor preparada para receber esse endereço. Abrir um HTML local e clicar em enviar não cria armazenamento, e-mail ou banco de dados automaticamente.

action

Define a URL que receberá os dados.

<form action="/inscricoes" method="post">
  ...
</form>

Se action for omitido, o envio ocorre para a URL atual. Mesmo assim, prefira ser explícito quando isso melhorar a clareza do projeto.

method

Os valores mais usados são get e post.

<form action="/buscar" method="get">...</form>
<form action="/contatos" method="post">...</form>

GET

POST

Dados aparecem na URL como consulta.

Dados são enviados no corpo da requisição.

Bom para busca, filtro e leitura.

Bom para criar ou alterar dados.

URL pode ser compartilhada e favoritada.

Dados não ficam normalmente na URL.

Limitado por tamanho prático da URL.

Aceita payloads maiores, conforme servidor.

Exemplo GET:

<form action="/buscar" method="get">
  <label for="termo">O que deseja buscar?</label>
  <input id="termo" name="q" type="search">
  <button type="submit">Buscar</button>
</form>

Uma busca por HTML pode gerar:

/buscar?q=HTML

enctype

Define a codificação quando o método é POST.

Valor

application/x-www-form-urlencoded

Padrão para campos textuais comuns.

multipart/form-data

Necessário quando existe upload de arquivo.

<form action="/documentos" method="post" enctype="multipart/form-data">
  <label for="arquivo">Documento</label>
  <input id="arquivo" name="arquivo" type="file">

Não adicione novalidate só para "sumir com os erros". Ele desativa uma camada útil de feedback e não substitui uma estratégia de validação acessível.

Todo campo precisa de um rótulo compreensível.

Associação explícita

<label for="nome-completo">Nome completo</label>
<input id="nome-completo" name="nome" type="text">

O valor de for deve ser exatamente igual ao id.

Benefícios:

  • leitores de tela anunciam o rótulo com o campo;
  • clicar no rótulo posiciona o foco no campo;
  • a área de interação fica maior;
  • mensagens e instruções ficam mais fáceis de relacionar.

Associação por envolvimento

Também é possível envolver o controle:

<label>
  Nome completo
  <input name="nome" type="text">
</label>

A associação explícita com for e id costuma ser mais fácil de manter em layouts complexos.

Placeholder não substitui label

<!-- Inadequado: não há rótulo persistente. -->
<input name="email" type="email" placeholder="Digite seu e-mail">

<!-- Melhor. -->
<label for="email">E-mail</label>
<input
  id="email"
  name="email"
  type="email"
  placeholder="nome@example.com">

O placeholder desaparece durante a digitação, pode ter contraste insuficiente e costuma ser confundido com valor preenchido.

Instrução e erro relacionados

<label for="senha">Senha</label>
<p id="ajuda-senha">Use pelo menos 12 caracteres.</p>
<input
  id="senha"
  name="senha"
  type="password"
  minlength="12"
  aria-describedby="ajuda-senha"
  required>

aria-describedby permite que tecnologias assistivas associem a instrução ao campo.

input é um elemento vazio: em HTML, ele não possui conteúdo nem tag de fechamento.

<input id="usuario" name="usuario" type="text">

Não escreva:

<!-- Incorreto em HTML. -->
<input>valor</input>

Se um navegador não reconhecer o valor de type, ele normalmente o trata como text. Isso favorece compatibilidade progressiva, mas não dispensa testes.

email

<label for="email">E-mail</label>
<input
  id="email"
  name="email"
  type="email"
  autocomplete="email"
  required>

O navegador pode mostrar teclado adequado em dispositivos móveis e verificar uma estrutura básica. Isso não comprova que a caixa postal existe.

Para vários endereços:

<label for="participantes">E-mails dos participantes</label>
<input id="participantes" name="participantes" type="email" multiple>

password

<label for="senha">Senha</label>
<input
  id="senha"
  name="senha"
  type="password"
  autocomplete="new-password"
  minlength="12"
  required>

Ocultar visualmente os caracteres não criptografa a senha. Use HTTPS, processamento seguro e armazenamento com hash apropriado no servidor.

Tokens úteis:

  • autocomplete="current-password" para senha atual;
  • autocomplete="new-password" para criação ou troca de senha;
  • autocomplete="username" para identificador da conta.

<label for="telefone">Telefone</label>
<input
  id="telefone"
  name="telefone"
  type="tel"
  autocomplete="tel"
  inputmode="tel">

tel não impõe um formato universal porque números variam entre países. Valide conforme os requisitos reais do sistema.

url

<input

  name="portfolio"
  type="url"
  placeholder="https://example.com">

<search>
  <form action="/buscar" method="get">
    <label for="busca">Buscar cursos</label>
    <input id="busca" name="q" type="search">
    <button type="submit">Buscar</button>
  </form>
</search>

O tipo search expressa a finalidade e pode receber comportamentos visuais específicos do navegador.

number

<label for="quantidade">Quantidade de ingressos</label>
<input
  id="quantidade"
  name="quantidade"
  type="number"
  min="1"
  max="5"
  step="1"
  value="1">

Use number quando o valor será tratado como número e controles de incremento fizerem sentido. CPF, CEP, matrícula e cartão não são quantidades matemáticas; geralmente devem ser texto.

<label for="satisfacao">Satisfação de 0 a 10</label>
<input

  name="satisfacao"
  type="range"
  min="0"
  max="10"
  step="1"
  value="5">
<output for="satisfacao">5</output>

O valor atual deve ficar perceptível. JavaScript pode sincronizar o output durante a interação.

color

<label for="cor">Cor do perfil</label>
<input id="cor" name="cor" type="color" value="#e34f26">

Checkbox: zero, uma ou várias escolhas

<fieldset>
  <legend>Assuntos de interesse</legend>

  <div>
    <input id="interesse-html" name="interesses" type="checkbox" value="html">
    <label for="interesse-html">HTML</label>
  </div>

  <div>
    <input id="interesse-css" name="interesses" type="checkbox" value="css">
    <label for="interesse-css">CSS</label>
  </div>

  <div>
    <input id="interesse-js" name="interesses" type="checkbox" value="javascript">
    <label for="interesse-js">JavaScript</label>
  </div>
</fieldset>

Um checkbox desmarcado normalmente não envia par nome–valor. O servidor deve lidar com a ausência.

Para uma confirmação obrigatória:

<input id="termos" name="aceitou_termos" type="checkbox" value="sim" required>
<label for="termos">Li e aceito os termos de uso</label>

Não deixe a caixa previamente marcada para consentimento que precisa ser livre e consciente.

Radio: uma opção do grupo

Todos os radios do mesmo grupo usam o mesmo name e valores diferentes.

<fieldset>
  <legend>Turno preferido</legend>

  <div>
    <input id="turno-manha" name="turno" type="radio" value="manha" required>
    <label for="turno-manha">Manhã</label>
  </div>

  <div>
    <input id="turno-tarde" name="turno" type="radio" value="tarde">
    <label for="turno-tarde">Tarde</label>
  </div>

  <div>
    <input id="turno-noite" name="turno" type="radio" value="noite">
    <label for="turno-noite">Noite</label>
  </div>
</fieldset>

fieldset cria o grupo semântico; legend explica a pergunta compartilhada.

file

<form action="/curriculos" method="post" enctype="multipart/form-data">
  <label for="curriculo">Currículo em PDF</label>
  <input
    id="curriculo"
    name="curriculo"
    type="file"
    accept="application/pdf"
    required>

  <button type="submit">Enviar currículo</button>
</form>

Para múltiplos arquivos:

<input
  id="anexos"
  name="anexos"
  type="file"
  accept="image/png,image/jpeg"
  multiple>

accept orienta a seleção, mas não é barreira de segurança. O servidor deve verificar extensão, tipo real, conteúdo, tamanho, nome e destino de armazenamento.

hidden

<input name="origem" type="hidden" value="campanha-setembro">

O campo fica invisível, mas seu valor pode ser inspecionado e alterado pela pessoa usuária. Nunca confie nele para preço, permissão, identidade ou qualquer regra sensível sem validação no servidor.

Tipos de botão em input

<input type="submit" value="Enviar">
<input type="reset" value="Limpar">
<input type="button" value="Executar ação">
<input type="image" src="enviar.png" alt="Enviar formulário">

Na maioria dos casos, prefira button, pois ele aceita texto e outros conteúdos de forma mais flexível.

<button type="submit">Enviar inscrição</button>

Evite reset: apagar todo o formulário por acidente costuma ser frustrante.

textarea

Use para texto com várias linhas.

<label for="mensagem">Mensagem</label>
<textarea
  id="mensagem"
  name="mensagem"
  rows="6"
  cols="40"
  minlength="20"
  maxlength="1000"
  required></textarea>

O valor inicial de textarea fica entre as tags. Evite espaços acidentais:

<textarea name="observacao">Texto inicial</textarea>

<label for="campus">Campus</label>
<select id="campus" name="campus" required>
  <option value="">Selecione uma opção</option>
  <option value="aclimacao">Aclimação</option>
  <option value="paulista">Paulista</option>
  <option value="vila-olimpia">Vila Olímpia</option>
</select>

O texto visível pode ser amigável; value deve ser estável para o sistema.

optgroup

<label for="curso">Curso</label>
<select id="curso" name="curso">
  <optgroup label="Tecnologia">
    <option value="ads">Análise e Desenvolvimento de Sistemas</option>
    <option value="si">Sistemas de Informação</option>
  </optgroup>
  <optgroup label="Design">
    <option value="design-digital">Design Digital</option>
  </optgroup>

Seleção múltipla

<label for="trilhas">Trilhas desejadas</label>
<select id="trilhas" name="trilhas" multiple size="4">
  <option value="frontend">Front-end</option>
  <option value="backend">Back-end</option>
  <option value="dados">Dados</option>
  <option value="ux">UX</option>
</select>

Explique como selecionar vários itens, porque o gesto varia conforme sistema e dispositivo. Muitas vezes checkboxes são mais claros para poucas opções.

datalist

Fornece sugestões, mas geralmente permite digitar outro valor.

<label for="cidade">Cidade</label>
<input id="cidade" name="cidade" type="text" list="cidades">

<datalist id="cidades">
  <option value="São Paulo"></option>
  <option value="Campinas"></option>
  <option value="Santos"></option>
</datalist>

Use select quando a escolha deve ficar restrita às opções. Use datalist quando sugestões forem úteis, mas outros valores continuarem válidos.

fieldset agrupa controles relacionados. legend nomeia o grupo.

<fieldset>
  <legend>Dados pessoais</legend>

  <label for="nome">Nome completo</label>
  <input id="nome" name="nome" type="text" autocomplete="name">

  <label for="data-nascimento">Data de nascimento</label>
  <input id="data-nascimento" name="data_nascimento" type="date">
</fieldset>

É especialmente importante para grupos de radio e checkbox, pois cada opção tem seu próprio rótulo, enquanto a legenda comunica a pergunta comum.

Desabilitar um grupo

<fieldset disabled>
  <legend>Etapa indisponível</legend>
  <label for="codigo-convite">Código do convite</label>
  <input id="codigo-convite" name="codigo_convite" type="text">
</fieldset>

Controles desabilitados geralmente não são enviados. Não use isso se o servidor depende dos valores.

Organização visual não substitui organização semântica

Uma borda em CSS pode parecer um grupo, mas não comunica a relação às tecnologias assistivas. Use fieldset e legend quando houver grupo lógico.

Dentro de um formulário, declare sempre o type do botão.

<button type="submit">Enviar</button>
<button type="button">Mostrar ajuda</button>
<button type="reset">Limpar tudo</button>

Tipo

Comportamento

submit

Valida e envia o formulário.

button

Não possui ação padrão; aguarda comportamento programado.

reset

Restaura valores iniciais. Use com cautela.

Se type for omitido dentro de um form, o botão normalmente age como submit. Isso pode enviar o formulário acidentalmente.

Botões com destinos diferentes

Um botão de envio pode sobrescrever atributos do formulário:

<form action="/rascunhos" method="post">
  <label for="titulo">Título</label>
  <input id="titulo" name="titulo" type="text">

  <button type="submit">Salvar rascunho</button>
  <button type="submit" formaction="/publicacoes">Publicar</button>
</form>

Outros atributos relacionados são formmethod, formenctype, formtarget e formnovalidate. Use-os somente quando a interface deixar o resultado claro.

Marque obrigatoriedade no texto

<p>Campos marcados com "obrigatório" devem ser preenchidos.</p>

<label for="nome">Nome completo (obrigatório)</label>
<input id="nome" name="nome" type="text" required>

Não dependa somente de asterisco, cor ou atributo técnico para comunicar a exigência.

Validação do cliente não é segurança

Qualquer pessoa pode alterar o HTML, desativar JavaScript ou enviar requisições diretamente. O servidor deve validar novamente:

  • presença;
  • tipo e formato;
  • limites;
  • autorização;
  • regras de negócio;
  • arquivos enviados;
  • consistência entre campos.

O atributo autocomplete ajuda navegadores e gerenciadores de senha a preencher dados conhecidos.

<label for="nome">Nome completo</label>
<input id="nome" name="nome" type="text" autocomplete="name">

<label for="email">E-mail</label>
<input id="email" name="email" type="email" autocomplete="email">

<label for="cep">CEP</label>
<input
  id="cep"
  name="cep"
  type="text"
  autocomplete="postal-code"
  inputmode="numeric">

Tokens comuns:

  • name, given-name, family-name;
  • email, tel;
  • street-address, address-line1, address-level2, postal-code;
  • organization;
  • username, current-password, new-password;
  • one-time-code.

Não bloqueie colagem de senha

Permitir colagem ajuda o uso de gerenciadores de senha e reduz erros. Não implemente bloqueios de paste.

Dados sensíveis

  • colete somente o necessário;
  • explique a finalidade;
  • use HTTPS;
  • não coloque senha, token ou dado pessoal em GET;
  • defina retenção e acesso no backend;
  • não confie em hidden para segurança.

Foco

Evite autofocus indiscriminado. Ele pode deslocar o foco sem aviso, abrir teclado em celulares e atrapalhar tecnologias assistivas.

GET para leitura

<form action="/cursos" method="get">
  <label for="area">Área</label>
  <select id="area" name="area">
    <option value="">Todas</option>
    <option value="tecnologia">Tecnologia</option>
    <option value="design">Design</option>
  </select>
  <button type="submit">Filtrar</button>
</form>

A URL resultante pode ser compartilhada:

/cursos?area=tecnologia

POST para criação ou alteração

<form action="/inscricoes" method="post">
  <label for="email-inscricao">E-mail</label>
  <input id="email-inscricao" name="email" type="email" required>
  <button type="submit">Realizar inscrição</button>
</form>

POST não é criptografia

POST apenas coloca os dados no corpo da requisição em vez da URL. Sem HTTPS, os dados podem trafegar sem proteção adequada.

Responsabilidades do servidor

O backend deve:

  • validar e normalizar entradas;
  • aplicar autorização;
  • usar consultas parametrizadas ao acessar banco de dados;
  • escapar saídas conforme o contexto;
  • proteger ações contra CSRF quando necessário;
  • limitar requisições e uploads;
  • registrar erros sem expor dados sensíveis;
  • devolver mensagens úteis e seguras.

Token CSRF

Alguns frameworks inserem um token oculto:

<input name="csrf_token" type="hidden" value="valor-gerado-pelo-servidor">

O valor deve ser criado e validado pelo servidor. Copiar esse exemplo estático não implementa proteção.

Observação sobre o botão de rascunho

O botão type="button" não faz nada sozinho. Para implementar o rascunho, registre um evento em js/validacao.js e carregue-o com defer:

<script src="js/validacao.js" defer></script>

Evite onclick diretamente no HTML.

Teste a validação nativa

  1. Tente enviar tudo vazio.
  2. Observe qual campo recebe foco.
  3. Digite um e-mail sem @.
  4. Digite matrícula com menos de oito algarismos.
  5. Não selecione o turno.
  6. Digite uma mensagem curta.
  7. tente anexar um arquivo não PDF.

As mensagens variam por navegador e idioma.

Teste com teclado

  1. Use Tab para avançar.
  2. Use Shift + Tab para voltar.
  3. Use setas para navegar no grupo de radio.
  4. Use espaço para marcar checkboxes.
  5. Confirme que o foco é visível.
  6. Verifique se a ordem acompanha a leitura visual.

Não use valores positivos de tabindex para "forçar" a ordem. Corrija a ordem do próprio HTML.

Inspecione a requisição

O endpoint de exemplo pode não existir, mas você pode observar a tentativa:

  1. abra as ferramentas do desenvolvedor;
  2. abra a guia Network ou Rede;
  3. preencha e envie o formulário;
  4. selecione a requisição;
  5. examine URL, método, cabeçalhos e dados enviados;
  6. confirme que cada chave corresponde ao name esperado.

Teste GET sem backend

Troque temporariamente o formulário por uma busca:

<form action="" method="get">
  <label for="teste">Termo de teste</label>
  <input id="teste" name="q" type="search">
  <button type="submit">Testar GET</button>
</form>

Ao enviar, procure ?q=... na barra de endereço.

Problema

Correção

Usar apenas placeholder

O rótulo desaparece e pode não ser anunciado corretamente.

Adicione label.

Esquecer name

O valor não participa do envio.

Defina uma chave estável.

Repetir id

Relações de rótulo e scripts ficam ambíguas.

Use um id único.

Radio com nomes diferentes

Mais de uma opção pode ser marcada.

Use o mesmo name no grupo.

Upload sem multipart/form-data

O arquivo não é codificado adequadamente.

Ajuste enctype e use POST.

Botão sem type

Pode enviar o formulário sem intenção.

Declare submit ou button.

CPF como number

Remove significado de zeros e sugere cálculo.

Use text com inputmode.

Confiar em required no cliente

A regra pode ser contornada.

Valide novamente no servidor.

Usar GET para senha

Dado aparece na URL e em históricos.

Use POST sobre HTTPS.

Desabilitar campo necessário

O valor não é enviado.

Use readonly ou outro modelo de dados.

Esconder erro apenas com cor

Parte do público não percebe.

Use texto claro e associação ao campo.

Limpar tudo automaticamente após erro

A pessoa perde trabalho.

Preserve dados válidos e foque no erro.

Desafio 1 — diagnóstico

Encontre pelo menos oito problemas:

<form action="/cadastro" method="get">
  <input id="nome" placeholder="Nome">
  <input id="nome" name="email" type="text" placeholder="E-mail">

  <p>Turno</p>
  <input id="manha" name="manha" type="radio">
  <label for="manha">Manhã</label>
  <input id="noite" name="noite" type="radio">
  <label for="noite">Noite</label>

  <input name="senha" type="password">
  <button>Cadastrar</button>
</form>

Desafio 2 — pesquisa com GET

Crie um formulário com:

  • campo de busca chamado q;
  • seleção de categoria chamada categoria;
  • filtro de data inicial;
  • botão "Filtrar resultados";
  • método GET;
  • rótulos para todos os controles.

Desafio 3 — contato com POST

Crie um formulário com:

  • nome, e-mail, assunto e mensagem;
  • assunto escolhido em select;
  • mensagem entre 20 e 1000 caracteres;
  • cópia para o remetente usando checkbox;
  • botão de envio explícito;
  • POST para /mensagens.

Uma possível correção do desafio 1

<form action="/cadastros" method="post">
  <div>
    <label for="nome">Nome completo</label>
    <input id="nome" name="nome" type="text" autocomplete="name" required>
  </div>

  <div>
    <label for="email">E-mail</label>
    <input id="email" name="email" type="email" autocomplete="email" required>
  </div>

  <fieldset>
    <legend>Turno</legend>

    <input id="manha" name="turno" type="radio" value="manha" required>
    <label for="manha">Manhã</label>

    <input id="noite" name="turno" type="radio" value="noite">
    <label for="noite">Noite</label>
  </fieldset>

  <div>
    <label for="senha">Senha</label>
    <input
      id="senha"
      name="senha"
      type="password"
      autocomplete="new-password"
      minlength="12"
      required>
  </div>

  <button type="submit">Cadastrar</button>
</form>

Problemas corrigidos: método inadequado, ausência de rótulos, name ausente, id repetido, tipo de e-mail incorreto, grupo radio com nomes diferentes, radios sem value, ausência de fieldset e legend, senha sem rótulo e botão sem tipo explícito.
