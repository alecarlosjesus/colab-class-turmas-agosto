Neste Codelab, você aprenderá os fundamentos de Git e GitHub enquanto cria o primeiro histórico do projeto Conecta Campus.

Ao final, você terá:

  • um repositório Git no seu computador;
  • arquivos preparados e registrados em commits;
  • um repositório conectado ao GitHub;
  • um ciclo de push e pull concluído;
  • o marco v0.1 do Conecta Campus publicado;
  • um histórico que mostra como o projeto evoluiu.

O que você precisa

  • Conta ativa no GitHub.
  • Permissão para instalar programas no computador.
  • Visual Studio Code ou outro editor de texto.
  • Navegador atualizado.
  • Conexão com a internet para a parte do GitHub.
  • Uma pasta conhecida para guardar seus projetos.

Regra principal deste Codelab

Execute uma ação por vez. Depois de cada ação importante, confira o resultado antes de avançar.

Atenção: substitua SEU-USUARIO, SEU NOME COMPLETO e SEU-EMAIL pelos seus próprios dados. Nunca publique senha, token, chave de API ou arquivo .env.

Como ler os comandos

Os comandos devem ser digitados no terminal. Se algum exemplo externo mostrar o símbolo $, não o digite: ele representa apenas o indicador de que o terminal está pronto.

Imagine que você salvou o mesmo trabalho com estes nomes:

projeto-final.zip
projeto-final-agora-vai.zip
projeto-final-certo-2.zip

Esses nomes tentam mostrar a evolução do trabalho, mas não respondem claramente:

  • o que mudou;
  • quem realizou a mudança;
  • quando a mudança aconteceu;
  • por que ela foi feita;
  • qual versão deve ser usada.

Um sistema de controle de versões registra a evolução do projeto em um histórico consultável.

O que é Git?

Git é um sistema de controle de versões instalado no computador. Ele permite registrar mudanças, comparar versões e consultar o histórico mesmo sem internet.

O que é GitHub?

GitHub é uma plataforma on-line que hospeda repositórios Git e acrescenta recursos de compartilhamento e colaboração.

Git e GitHub não são a mesma coisa

Git

GitHub

Funciona no computador.

Funciona como serviço on-line.

Cria commits localmente.

Hospeda o repositório remoto.

Pode ser usado sem internet.

Precisa de internet para sincronização.

Controla o histórico.

Facilita compartilhamento e colaboração.

Você pode usar Git sem GitHub. Porém, para compartilhar o histórico ou acessá-lo em outro computador, normalmente utilizará um serviço remoto como o GitHub.

Instalação no Windows

  1. Acesse git-scm.com/install/windows.
  2. Baixe o instalador x64, exceto se o computador usar processador ARM64.
  3. Execute o instalador.
  4. Mantenha os componentes padrão, incluindo Git Bash e Git Credential Manager, quando oferecidos.
  5. Escolha o Visual Studio Code como editor padrão somente se ele já estiver instalado.
  6. Na configuração do branch inicial, escolha main ou defina esse nome depois da instalação.
  7. Mantenha a opção recomendada de PATH, que permite usar Git no terminal e em outros programas.
  8. Conclua a instalação.
  9. Feche os terminais que estavam abertos e abra um novo terminal.

Atenção: as telas do instalador podem mudar. O objetivo é ter Git, Git Bash e autenticação HTTPS funcionando. Não escolha opções avançadas apenas porque parecem mais completas.

macOS e Linux

  • macOS: consulte git-scm.com/install/mac.
  • Linux: use o gerenciador de pacotes da sua distribuição e consulte git-scm.com/install/linux.

Os comandos Git utilizados neste Codelab são os mesmos. O que muda é a forma de instalação e o terminal disponível.

Verificar a instalação

Abra o Git Bash, PowerShell ou terminal integrado do Visual Studio Code e execute:

git --version

Entenda o comando:

  • git: chama o programa Git;
  • --version: solicita a versão instalada;
  • o comando apenas consulta uma informação e não altera arquivos.

O resultado será parecido com:

git version 2.x.x

A versão exata pode ser diferente. O importante é o Git responder sem erro.

Configurar sua identidade

O nome e o e-mail abaixo não são sua senha. Eles identificam a autoria dos commits.

git config --global user.name "SEU NOME COMPLETO"
git config --global user.email "SEU-EMAIL"
git config --global init.defaultBranch main

Entenda cada parte:

  • git config: altera ou consulta configurações do Git;
  • --global: aplica a configuração ao seu usuário nesse computador;
  • user.name: define o nome do autor;
  • user.email: define o e-mail do autor;
  • init.defaultBranch main: define main como nome padrão do primeiro branch.

As aspas no nome preservam os espaços. Esses comandos normalmente não exibem mensagem quando funcionam.

Privacidade: se não quiser publicar seu e-mail pessoal nos commits, configure no GitHub um endereço noreply reconhecido pela sua conta.

Conferir a configuração

git config --global --list

Procure as seguintes chaves na saída:

user.name=
user.email=
init.defaultbranch=main

Prática WP02

Registre em suas anotações:

  • versão instalada do Git;
  • valor de user.name;
  • apenas o domínio do e-mail, sem expor o endereço completo;
  • nome do branch padrão.

Se algo estiver incorreto, repita apenas o comando de configuração correspondente.

O Git não registra automaticamente tudo o que você digita. Uma mudança percorre três áreas principais.

1. Diretório de trabalho

É a pasta visível do projeto. Nela você cria, edita e apaga arquivos.

2. Área de preparação

Também chamada de stage ou index, guarda a seleção do que entrará no próximo commit.

3. Repositório local

Fica na pasta oculta .git e guarda o histórico do projeto.

O fluxo básico é:

Editar arquivos → Preparar com git add → Registrar com git commit

Atenção: não altere nem apague manualmente a pasta .git. Excluí-la remove o histórico local, embora os arquivos de trabalho continuem visíveis.

Nesta etapa, você criará o repositório local e os dois primeiros arquivos do projeto.

Criar e abrir a pasta

Posicione o terminal na pasta em que você guarda seus projetos. Depois execute um comando por vez:

mkdir conecta-campus
cd conecta-campus
code .

Entenda cada comando:

  • mkdir conecta-campus: cria uma pasta chamada conecta-campus;
  • cd conecta-campus: entra na nova pasta;
  • code .: abre no Visual Studio Code a pasta atual, representada pelo ponto.

Se code . não funcionar, abra o Visual Studio Code pelo menu e escolha Arquivo > Abrir Pasta.

Evite criar o projeto dentro de uma pasta temporária ou em um local que você não consegue encontrar depois.

Inicializar o Git

No terminal aberto dentro de conecta-campus, execute:

git init -b main
git status
  • git init: transforma a pasta comum em um repositório Git;
  • -b main: cria o branch inicial com o nome main;
  • git status: mostra o estado atual sem alterar arquivos.

O resultado deve indicar que o repositório está vazio e ainda não possui commits.

Criar o README

No Visual Studio Code, crie na raiz do projeto o arquivo README.md.

Digite:

# Conecta Campus

Guia acadêmico de serviços, ambientes e recursos de acessibilidade.

## Situação do projeto

Versão inicial em construção durante o primeiro semestre de ADS.

## Autor

Seu nome completo

O símbolo # cria o título principal. ## cria um subtítulo. Linhas em branco separam os blocos.

Criar o .gitignore

Crie na raiz um arquivo chamado exatamente .gitignore. O ponto faz parte do nome.

Digite:

.vscode/
.DS_Store
Thumbs.db
*.log
.env
node_modules/
dist/

Esse arquivo registra padrões que não devem entrar no histórico:

  • / no final indica uma pasta;
  • * é um curinga;
  • *.log representa qualquer arquivo terminado em .log;
  • .env protege arquivos comuns de variáveis locais;
  • node_modules/ e dist/ serão úteis em etapas futuras do curso.

Importante: .gitignore não apaga arquivos e não torna seguros segredos que já foram publicados. Nunca adicione senhas, tokens, chaves de API ou .env ao commit.

Conferir o estado

git status

README.md e .gitignore devem aparecer como untracked.

Agora você transformará os arquivos criados em um histórico legível.

Preparar os arquivos conscientemente

git add README.md .gitignore
git status

O primeiro comando seleciona os dois arquivos para o próximo commit. O segundo confirma o resultado.

Eles devem aparecer em Changes to be committed, indicando o estado staged.

Por que não começar com git add .?

O ponto em git add . prepara tudo que não estiver ignorado. Isso é útil, mas pode incluir arquivos acidentais. No primeiro commit, nomear os arquivos deixa a decisão mais clara.

Criar o primeiro commit

git commit -m "docs: inicia documentação do Conecta Campus"
git status

Entenda o comando:

  • commit: cria um registro no histórico;
  • -m: permite escrever a mensagem no próprio comando;
  • docs:: informa que a mudança está relacionada à documentação;
  • a mensagem explica claramente o que foi feito.

Se nada mudou depois do commit, git status deverá informar:

working tree clean

Evite mensagens vagas como update, teste, alterações ou coisas.

Consultar o histórico

git log --oneline
  • log: consulta os commits;
  • --oneline: mostra cada commit em uma linha curta;
  • o código no início da linha é uma forma curta do hash do commit.

Comparar uma nova alteração

No primeiro parágrafo do README.md, acrescente esta frase:

O projeto será desenvolvido de forma incremental.

Salve o arquivo e execute:

git diff
git status

Em git diff:

  • linhas iniciadas por - representam conteúdo anterior ou removido;
  • linhas iniciadas por + representam conteúdo novo ou acrescentado;
  • o comando apenas consulta diferenças e não altera arquivos.

Agora registre a mudança:

git add README.md
git commit -m "docs: explica evolução incremental"
git log --oneline
git status

O commit mais recente aparece primeiro no log. Ao final, o diretório de trabalho deve estar limpo.

Prática WP04

  1. Faça uma pequena melhoria no README.md.
  2. Salve o arquivo.
  3. Use git diff antes de preparar.
  4. Prepare somente o arquivo alterado.
  5. Crie um terceiro commit com mensagem descritiva.
  6. Execute git log --oneline.
  7. Explique o que o diff ajudou você a conferir.

Até aqui, o histórico existe somente no seu computador. Agora você criará um repositório vazio no GitHub e conectará as duas cópias.

Criar o repositório remoto

  1. Acesse github.com e entre em sua conta.
  2. Clique na opção de criação e escolha New repository.
  3. Em Repository name, digite conecta-campus.
  4. Na descrição, digite Guia acadêmico de serviços e acessibilidade.
  5. Escolha a visibilidade indicada pelo professor.
  6. Não marque README, .gitignore ou licença, porque esses arquivos já existem no computador.
  7. Clique em Create repository.
  8. Mantenha aberta a página de configuração rápida.

Se você criar arquivos localmente e também no GitHub antes da primeira sincronização, produzirá dois históricos separados. Neste roteiro, o repositório remoto deve começar vazio.

Adicionar o remoto

No terminal do projeto, execute:

git remote add origin https://github.com/SEU-USUARIO/conecta-campus.git
git remote -v

Entenda o primeiro comando:

  • remote: gerencia repositórios remotos;
  • add: cria uma associação;
  • origin: apelido convencional dado ao remoto principal;
  • a URL aponta para o repositório criado na sua conta.

O comando git remote -v deve mostrar duas linhas para origin: uma para receber (fetch) e outra para enviar (push).

Enviar o histórico

git push -u origin main

Entenda cada parte:

  • push: envia commits;
  • -u: registra a relação de acompanhamento entre os branches;
  • origin: é o apelido do remoto;
  • main: é o branch enviado.

Na primeira vez, o Git Credential Manager pode abrir o navegador para autenticação.

Segurança: o GitHub não usa a senha comum da conta como senha do Git no terminal. Nunca envie tokens por mensagem e nunca coloque credenciais em comandos, arquivos ou capturas de tela.

Conferir no navegador

Atualize a página do repositório e verifique:

  • [ ] README.md aparece renderizado.
  • [ ] .gitignore aparece na lista de arquivos.
  • [ ] A quantidade esperada de commits é mostrada.
  • [ ] O branch exibido é main.
  • [ ] Nenhum arquivo confidencial foi publicado.

Prática WP05

Se algum item estiver diferente, não execute comandos aleatórios. Use:

git status
git log --oneline
git remote -v

Identifique se o problema está nos arquivos, no histórico ou na conexão remota.

Confirmar que o trabalho local está limpo

git status

Repositório acadêmico criado na primeira semana do curso.

Trazer a mudança para o computador

Volte ao terminal e execute:

git status
git pull
git log --oneline
  • git pull: recebe e integra a alteração remota;
  • o novo commit deve aparecer no topo do histórico;
  • o README.md local deve conter a frase adicionada no GitHub.

Quando usar clone

Use clone quando um repositório remoto já existe e você precisa criar uma cópia local completa.

Não execute o comando dentro do repositório atual. Em outra pasta, como estudo opcional, seria possível usar:

git clone https://github.com/SEU-USUARIO/conecta-campus.git

O clone cria uma nova pasta com arquivos, histórico e origin configurado.

O repositório deve guardar mais do que comandos executados. Ele iniciará um documento vivo, atualizado ao longo do curso.

Estrutura esperada

conecta-campus/
├── docs/
│   └── tema-do-projeto.md
├── .gitignore
└── README.md

Esse bloco representa a estrutura; não deve ser executado no terminal.

Criar o documento vivo

No Visual Studio Code:

  1. Crie a pasta docs.
  2. Dentro dela, crie tema-do-projeto.md.
  3. Digite o conteúdo abaixo.
# Conecta Campus

## Problema

Alunos ingressantes nem sempre encontram rapidamente ambientes, serviços, horários e recursos de acessibilidade do campus.

## Público-alvo

- Estudantes ingressantes
- Pessoas que precisam localizar recursos acessíveis
- Visitantes em atividades acadêmicas

## Objetivo geral

Criar um guia web simples, responsivo e acessível para consultar locais e serviços acadêmicos.

## Primeira versão

A versão 1.0 usará HTML, CSS e JavaScript, com pesquisa, filtros e favoritos armazenados no navegador.

## Continuidade

No segundo semestre, a solução evoluirá para Node.js, React, TypeScript, Tailwind CSS e publicação na Vercel.

Não invente agora funcionalidades que pertencem a etapas futuras.

Registrar e publicar o documento

Execute um comando por vez:

git status
git add docs/tema-do-projeto.md
git commit -m "docs: registra tema do Conecta Campus"
git push
git log --oneline

Depois do primeiro push -u, o comando git push pode omitir origin main, pois a relação de acompanhamento já foi configurada.

  • [ ] README.md apresenta tema, situação e autoria.
  • [ ] .gitignore contém regras para .env, logs, node_modules e dist.
  • [ ] docs/tema-do-projeto.md contém problema, público, objetivo, primeira versão e continuidade.

Sintoma

Causa provável

Como confirmar e agir

git não é reconhecido

Terminal antigo ou PATH não configurado.

Reabra o terminal, execute git --version e confirme a instalação.

not a git repository

O terminal está fora da pasta correta ou git init não foi executado.

Use pwd e ls, entre em conecta-campus e confirme a existência de .git sem alterá-la.

Corrigir a URL de origin

Execute estes comandos somente se git remote -v mostrar uma URL incorreta:

git remote -v
git remote set-url origin https://github.com/SEU-USUARIO/conecta-campus.git
git remote -v

set-url altera a associação existente. Ele não cria um segundo origin.
