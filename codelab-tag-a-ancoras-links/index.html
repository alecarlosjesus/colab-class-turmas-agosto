🔗 Ideia central: um link é uma ponte entre dois endereços. O href informa o destino; o texto do link explica à pessoa para onde essa ponte leva.

A tag a, chamada de âncora, cria hiperlinks. Links conectam páginas, arquivos, seções, endereços de e-mail, telefones e outros recursos identificados por uma URL.

Neste codelab você construirá um pequeno site de três páginas e aprenderá a evitar links quebrados, textos ambíguos, abertura inesperada de abas e problemas relacionados a target="_blank".

Objetivos

  • compreender a anatomia da tag a;
  • distinguir URL absoluta, relativa à pasta e relativa à raiz;
  • navegar entre pastas com ./ e ../;
  • criar links para partes da mesma página;
  • conhecer mailto:, tel: e download;
  • usar target com intenção e segurança;
  • explicar o risco de window.opener e o papel de rel="noopener";
  • criar links acessíveis e fáceis de testar.

Um link básico possui tag de abertura, atributo href, conteúdo e tag de fechamento.

<a href="contato.html">Entre em contato</a>

Parte

Função

a

Identifica o elemento âncora.

href

Define o destino do hiperlink.

contato.html

URL do destino.

Entre em contato

Texto acessível e área clicável.

Quando href está presente, o link entra naturalmente na ordem do teclado e pode ser ativado com Enter.

Link não é apenas texto azul

A cor e o sublinhado são estilos padrão do navegador. O significado vem da tag e do href.

<!-- Navega para outra página. -->
<a href="cursos.html">Conheça os cursos</a>

<!-- Executa uma ação. -->
<button type="button">Abrir filtros</button>

Use link para navegação e botão para ação. Não crie um falso botão com href="#" ou javascript:void(0).

Use URLs absolutas principalmente para outros sites.

Prefira HTTPS

<a href="https://example.com">Site seguro por HTTPS</a>

Evite criar novos links http:// quando o destino oferece HTTPS. O HTTPS protege a comunicação durante o transporte, embora não garanta que o conteúdo do site seja confiável.

Um caminho relativo é calculado a partir da localização do arquivo atual.

Mesma pasta

De index.html para contato.html:

<a href="contato.html">Contato</a>

./contato.html também representa explicitamente a pasta atual:

<a href="./contato.html">Contato</a>

Entrar em uma subpasta

De index.html para cursos/desenvolvimento-web.html:

<a href="cursos/desenvolvimento-web.html">Desenvolvimento Web</a>

Voltar uma pasta

De cursos/desenvolvimento-web.html para o index.html da raiz:

<a href="../index.html">Voltar ao início</a>

Cada ../ sobe um nível:

./        pasta atual
../       sobe uma pasta
../../    sobe duas pastas

Link relativo à raiz do site

<a href="/contato.html">Contato</a>

A barra inicial / significa "comece na raiz do site". Isso costuma funcionar em um servidor, mas pode falhar quando o arquivo é aberto diretamente pelo sistema operacional ou quando o projeto está publicado dentro de uma subpasta.

Para exercícios abertos diretamente com file:///, prefira caminhos relativos como contato.html e ../index.html. Em produção, escolha a estratégia de URL compatível com a hospedagem.

Nomes de arquivos seguros

Prefira:

  • letras minúsculas;
  • palavras separadas por hífen;
  • sem espaços;
  • sem acentos em nomes de arquivo e pasta.
desenvolvimento-web.html
manual-do-aluno.pdf

Um fragmento aponta para um elemento que possui um id.

<nav aria-label="Sumário da página">
  <ul>
    <li><a href="#objetivos">Objetivos</a></li>
    <li><a href="#conteudo">Conteúdo</a></li>
    <li><a href="#exercicios">Exercícios</a></li>
  </ul>
</nav>

<section id="objetivos">
  <h2>Objetivos</h2>
</section>

<section id="conteudo">
  <h2>Conteúdo</h2>
</section>

<section id="exercicios">
  <h2>Exercícios</h2>
</section>

Regras para id

  • deve ser único na página;
  • não deve conter espaços;
  • deve permanecer estável se outros links apontarem para ele;
  • deve ser descritivo;
  • o valor em href="#..." deve corresponder exatamente ao id.

Link para o topo

Crie um ponto explícito:

<body id="topo">
  <!-- conteúdo -->
  <a href="#topo">Voltar ao topo</a>
</body>

Embora href="#" possa levar ao topo, um id descritivo comunica melhor a intenção e evita o uso do fragmento vazio como falso botão.

Link de salto para acessibilidade

<body>
  <a class="link-pular" href="#conteudo-principal">
    Pular para o conteúdo principal
  </a>

  <header>...</header>
  <main id="conteudo-principal">...</main>
</body>

Esse link permite que pessoas que usam teclado ignorem navegações repetidas.

mailto:

Abre o aplicativo de e-mail configurado pelo usuário.

<a href="mailto:contato@example.com">Enviar e-mail</a>

Com assunto:

<a href="mailto:contato@example.com?subject=D%C3%BAvida%20sobre%20o%20curso">
  Enviar dúvida por e-mail
</a>

Espaços e caracteres especiais precisam ser codificados na URL. Evite preencher mensagens extensas ou informações sensíveis diretamente no link.

tel:

<a href="tel:+5511999999999">Ligar para (11) 99999-9999</a>

O comportamento depende do dispositivo e dos aplicativos instalados.

sms:

<a href="sms:+5511999999999">Enviar SMS</a>

O suporte e o comportamento podem variar entre plataformas.

Evite javascript:

<!-- Evite. -->
<a href="javascript:abrirMenu()">Abrir menu</a>

<!-- Prefira. -->
<button type="button" id="botao-menu">Abrir menu</button>

URLs javascript: misturam comportamento com navegação, podem criar riscos de segurança e não funcionam como links reais.

target define o contexto de navegação usado para abrir o destino.

Valor

Comportamento

_self

Abre no contexto atual. É o padrão.

_blank

Normalmente abre nova aba; o navegador ou usuário pode escolher nova janela.

_parent

Abre no contexto pai, útil em documentos embutidos. Sem pai, age como _self.

_top

Abre no contexto de nível mais alto. Sem ancestrais, age como _self.

nome personalizado

Abre ou reutiliza um contexto com aquele nome.

Existe ainda _unfencedTop, destinado a um caso avançado de fenced frames. Ele raramente é necessário em sites comuns.

Comportamento padrão

<a href="contato.html">Contato</a>

É equivalente a:

<a href="contato.html" target="_self">Contato</a>

Abrir nova aba

<a
  href="https://developer.mozilla.org/"
  target="_blank"
  rel="noopener noreferrer">
  Abrir a MDN em nova aba
</a>

Não use _blank por padrão em todo link externo. A pessoa pode escolher abrir uma nova aba pelo navegador. Use-o somente quando a mudança de contexto fizer sentido e avise o que acontecerá.

<a
  href="https://developer.mozilla.org/"
  target="_blank"
  rel="noopener noreferrer">
  Referência MDN (abre em nova aba)
</a>

O risco clássico é conhecido como reverse tabnabbing. Em navegadores antigos ou cenários sem proteção, a página aberta poderia acessar window.opener e tentar redirecionar a aba original para uma página falsa.

Uma sequência possível seria:

  1. a pessoa clica em um link com target="_blank";
  2. o destino abre em outra aba;
  3. o destino obtém uma referência para a página original por window.opener;
  4. um script malicioso altera o endereço da aba original;
  5. a pessoa volta e encontra uma página falsa parecida com a verdadeira.

Proteção com noopener

<a
  href="https://site-externo.example"
  target="_blank"
  rel="noopener">
  Site externo (abre em nova aba)
</a>

noopener impede que o novo contexto receba acesso à página original por window.opener.

Proteção e privacidade com noreferrer

<a
  href="https://site-externo.example"
  target="_blank"
  rel="noopener noreferrer">
  Site externo (abre em nova aba)
</a>

noreferrer também evita o envio do cabeçalho HTTP Referer e implica o comportamento de noopener. Isso aumenta a privacidade, mas pode impedir que o site de destino saiba de onde veio a visita, afetando métricas legítimas.

Situação nos navegadores modernos

Navegadores atuais tratam target="_blank" em elementos a como se rel="noopener" estivesse presente. Mesmo assim, escrever rel="noopener" de forma explícita:

  • documenta a intenção de segurança;
  • ajuda em ambientes antigos ou incomuns;
  • facilita revisões de código;
  • não resolve, porém, o problema de usabilidade de abrir uma aba inesperadamente.

O principal cuidado atual não é afirmar que todo _blank moderno está vulnerável. É decidir se a nova aba é necessária, avisar a pessoa e manter uma proteção explícita quando apropriado.

Outros valores de rel

Valor

Significado comum

noopener

Remove acesso por window.opener.

noreferrer

Não envia referência e também protege o opener.

external

Indica que o recurso está fora do site atual.

nofollow

Indica que o autor não endossa o destino ou não quer influenciar rastreamento.

sponsored

Identifica link publicitário ou patrocinado.

ugc

Identifica conteúdo gerado por usuário.

author

Aponta para informações sobre autoria.

license

Aponta para a licença do conteúdo.

Não adicione valores sem entender o objetivo. external, por exemplo, não abre uma nova aba sozinho.

O texto do link deve indicar o destino mesmo quando lido fora do parágrafo.

<!-- Fraco e ambíguo. -->
<p>Para conhecer os cursos, <a href="cursos.html">clique aqui</a>.</p>

<!-- Melhor. -->
<p><a href="cursos.html">Conheça os cursos disponíveis</a>.</p>

Pessoas que usam leitores de tela podem listar todos os links da página. Dez links chamados "saiba mais" não ajudam a diferenciar destinos.

Imagens dentro de links

Quando uma imagem é o único conteúdo do link, o alt deve descrever a finalidade do link.

<a href="index.html">
  <img
    src="imagens/logo-html.svg"
    alt="Página inicial do Portal Campus"
    width="72"
    height="72">
</a>

Se o link já possui texto equivalente, uma imagem apenas decorativa pode usar alt="".

Estado da página atual

<nav aria-label="Navegação principal">
  <ul>
    <li><a href="index.html" aria-current="page">Início</a></li>
    <li><a href="cursos.html">Cursos</a></li>
  </ul>
</nav>

aria-current="page" informa qual link representa a página atual.

Não aninhe controles interativos

<!-- Incorreto. -->
<a href="matricula.html"><button>Matricular</button></a>

<!-- Correto para navegar. -->
<a href="matricula.html" class="link-destaque">Matricular</a>

Não coloque botão dentro de link nem link dentro de botão.

Não dependa apenas de cor

Links em textos devem possuir uma indicação visual que não dependa exclusivamente da cor, como sublinhado. Mantenha também um foco visível para navegação por teclado.

O atributo download sugere ao navegador que o destino seja baixado.

<a href="documentos/manual-do-aluno.pdf" download>
  Baixar manual do aluno (PDF, 2 MB)
</a>

Também é possível sugerir um nome:

<a
  href="documentos/manual-do-aluno.pdf"
  download="manual-conecta-campus.pdf">
  Baixar manual do aluno (PDF, 2 MB)
</a>

Limitações importantes

  • download funciona principalmente para URLs da mesma origem e para URLs blob: ou data:;
  • cabeçalhos enviados pelo servidor podem influenciar o nome e a forma de abertura;
  • configurações do navegador e do usuário podem alterar o comportamento;
  • informe formato e tamanho quando isso ajudar a pessoa a decidir.
<a href="documentos/calendario-2026.pdf" type="application/pdf">
  Abrir calendário acadêmico (PDF, 850 KB)
</a>

O atributo type é apenas uma dica; ele não substitui o Content-Type correto no servidor.

Teste manual

  1. Abra index.html.
  2. Ative cada link com o mouse.
  3. Repita usando Tab e Enter.
  4. Use o botão Voltar do navegador.
  5. Confirme o destino na barra de endereço.
  6. Verifique se os fragmentos chegam à seção correta.
  7. Confirme que links com nova aba avisam esse comportamento.

Diagnóstico de erro 404

Se um link falhar, confira:

  • nome exato do arquivo;
  • diferença entre maiúsculas e minúsculas;
  • extensão .html;
  • quantidade de ../;
  • existência da pasta;
  • acentos e espaços no nome;
  • endereço de publicação em subpasta.

Use as ferramentas do navegador

  1. Pressione F12.
  2. Abra Network ou Rede.
  3. Ative o link problemático.
  4. Observe a URL solicitada e o código de resposta.
  5. Um 404 significa que o recurso não foi encontrado naquele caminho.

Checklist

  • [ ] Todo a de navegação possui href real.
  • [ ] O texto informa o destino.
  • [ ] Caminhos relativos foram testados em todas as páginas.
  • [ ] Cada id usado por fragmento existe e é único.
  • [ ] _blank é usado somente quando justificado.
  • [ ] Links que abrem outra aba avisam o usuário.
  • [ ] rel="noopener" está explícito nos links _blank externos.
  • [ ] Links para arquivos informam formato e, quando possível, tamanho.
  • [ ] Não existe botão dentro de link.
  • [ ] Não existe javascript: usado como navegação.

Desafio 1 — caminhos

Escreva os links corretos:

  1. cursos/index.html para documentos/manual-do-aluno.pdf.
  2. cursos/desenvolvimento-web.html para contato.html.
  3. contato.html para cursos/desenvolvimento-web.html#avaliacao.

Desafio 2 — segurança e experiência

Corrija:

<a href="https://site-externo.example" target="_blank">Clique aqui</a>

A correção precisa:

  • explicar o destino;
  • avisar sobre a nova aba;
  • incluir a proteção apropriada.

Desafio 3 — semântica

Corrija:

<a href="#" onclick="enviarFormulario()">
  <button>Enviar</button>
</a>

O controle executa uma ação; não navega.

Respostas dos caminhos iniciais

  1. De index.html para cursos/index.html:
<a href="cursos/index.html">Cursos</a>
  1. De cursos/index.html para contato.html:
<a href="../contato.html">Contato</a>
  1. De cursos/desenvolvimento-web.html para o PDF:
<a href="../documentos/manual-do-aluno.pdf">Manual</a>

Observe: a partir de cursos/desenvolvimento-web.html, um ../ leva à raiz, onde está a pasta documentos.

Resumo de decisão

  • Outro site: URL absoluta.
  • Arquivo do projeto: URL relativa.
  • Seção: fragmento #id.
  • Navegação: a com href real.
  • Ação: button.
  • Nova aba: use apenas quando necessário, avise e proteja.
